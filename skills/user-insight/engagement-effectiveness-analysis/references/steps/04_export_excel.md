# Step 4: Export the Detail Workbook

## Goal

Produce the seven-sheet XLSX that holds **all** retrieved campaign data, so any
number in the report can be traced back to the raw rows behind it.

## Input

- `tmp/analysis.json` (from Step 3)
- `tmp/raw_*.json` (from Step 2)
- `assets/detail_workbook_spec.md` — the seven sheets and their columns

## Output

- `output/{strategy}_明细数据_{YYYYMMDD}.xlsx`

## Executor

Orchestrator running the script. **A script must generate it; hand-assembled
workbooks are not accepted.**

## Validation Gate

`scripts/validate_excel.py <xlsx>`

## Failure Handling

- Gate exit 1 → **FATAL**.
- A thin sheet is **EMPTY**, and is labelled rather than dropped.

## Flow

### Sub-step 4.1 — Export

```bash
$PY $S/scripts/export_detail_excel.py --analysis tmp/analysis.json --raw-dir tmp \
      --out-dir output --strategy-name "<name>"
```

`PY` must be the interpreter Step 0 resolved. `export_detail_excel.py` is the one
script in the skill needing `openpyxl`, and that path is machine-specific by
construction.

**Decision based on exit code:**

- **IF exit 0** → proceed to 4.2.
- **IF exit 1 (missing openpyxl)** → re-run Step 0 without `--no-install`, then stop.
- **IF exit 1 (other)** → **FATAL**, quote the error.

### Sub-step 4.2 — Validate the workbook

```bash
$PY $S/scripts/validate_excel.py <xlsx>
```

**Decision based on exit code:**

- **IF exit 0** → proceed to Step 5.
- **IF exit 1** → report which sheet is missing or short, and stop.

### Sub-step 4.3 — Confirm the four export rules held

| Rule | Why |
|---|---|
| Everything goes on the sheet — no filtering, no premature aggregation | the workbook is the evidence base; a pre-filtered sheet cannot be used to check the report's arithmetic |
| A sheet missing in mode B is **kept**, with an explanation row naming the reason | a silently absent sheet reads as "this campaign had no such data" |
| Column names match the platform / tracking-plan wording verbatim, original metric keys preserved | a renamed key breaks the join back to the platform |
| Generated by script only | hand-built workbooks drift from `detail_workbook_spec.md` with no gate to catch it |

**Decision:**

- **IF a missing sheet was deleted rather than annotated** → **FATAL**.
- **IF a column was renamed for readability** → **FATAL**.

---

**After completion, proceed to Step 5 (`steps/05_report.md`).**

## Error Handling Summary

| Scenario | Action | Status |
|---|---|---|
| Export exit 0, gate exit 0 | Proceed to Step 5 | SUCCESS |
| `openpyxl` unavailable | Re-run Step 0 without `--no-install` | FATAL |
| Gate exit 1 — sheet missing | Report the sheet, stop | FATAL |
| Gate exit 1 — sheet under `--min-rows` | Report the sheet, stop | FATAL |
| A mode B sheet deleted instead of annotated | Stop and fix | FATAL |
| A metric key renamed | Stop and fix | FATAL |

## Notes

- `--min-rows` defaults to 2 (header plus at least one data row).
- Sheet 7 holds the flattened raw endpoint response so the workbook stays traceable
  after the run directory is gone.
- The filename carries the run date, which is why the workbook and the report share
  a stamp and can be paired visually.
