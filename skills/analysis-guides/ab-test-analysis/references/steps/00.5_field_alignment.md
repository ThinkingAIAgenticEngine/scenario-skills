# Step 0b - Field Alignment

> Procedure file for **Step 0b** in `SKILL.md`.
> Alias tables, value-domain rules and the mapping contract: `references/field_mapping.md`.

## Goal

Turn the business wording the user speaks into **field names that actually exist in the project**, and
write a machine-checkable `field_mapping.json` holding the group field, the exposure event, the
success/guardrail events, and the **cohort contract block** that Step 1 must obey. This is the cheapest
correction point on the whole chain: one wrong name here makes Step 1 return nothing, which is then
misread as "the experiment had no traffic".

## Input

| Source | Content |
|--------|---------|
| User | Answers to the five field facts: group field and its type, value domain and the control/treatment values, exposure event, success events, guardrail events |
| Project metadata | `ae-cli` event list and property list, used to confirm existence and type |
| Alias source | The alias tables in `references/field_mapping.md` |

## Output

`{ws}/tmp/field_mapping.json`, containing:

| Key | Meaning |
|-----|---------|
| `project_id` / `variant_field` / `variant_field_type` | Project and group field (including `event_property` / `user_property`) |
| `control_value` / `treatment_value` | The two real stored values, and which one is the control |
| `exposure_event` | The event that marks "the user entered the experiment" |
| `success_events` / `guardrail_events` | Success metrics and guardrail metrics |
| `cohort` | **Required**: `basis`, `order_enforced`, `denominator_column`, `numerator_columns` |
| `metrics` | Per-metric declaration: `numerator_column` for proportions; `basis` plus `distribution: user_level` for continuous inference |

## Executor

Orchestrator (alias normalisation and user confirmation), then the gate script for validation.

## Validation Gate

```bash
python scripts/check_field_mapping.py {ws}/tmp/field_mapping.json
```

Sequence: normalise aliases -> confirm existence -> confirm type -> check the value domain (exactly two
valid groups) -> map the group semantics -> write the mapping and run the gate. Any FAIL sends you back
to the user for confirmation. **Only a passing alignment may enter Step 1.**

## Failure Handling

| Situation | Status | Action |
|-----------|--------|--------|
| The field name cannot be found in the project | FATAL | Stop. Offer near-miss candidates for the user to pick; never guess one and query |
| The value domain is not two groups (three or more) | ERROR | Treat it as a multi-arm test (Boundary Statement item 5) or as the wrong field; go back to the user |
| The two groups are severely imbalanced | WARN | Clean dirty values first (empty, internal test group, unknown) and re-check; if it stays imbalanced, report it as a data-quality risk |
| The `cohort` block is missing or incomplete | ERROR | Supply `basis` / `order_enforced` / `denominator_column` / `numerator_columns` |
| `cohort.basis` is not the exposure caliber | ERROR | Set it back to `exposed_users_after_exposure` |
| A continuous metric does not declare the user-level exposed-cohort caliber | ERROR | Add `basis: per_user_over_exposed_cohort` and `distribution: user_level`; aggregate and payers-only calibers are rejected |

## Flow

1. Normalise the aliases: run the user's wording through the alias tables to get candidate standard names.
2. `IF the candidate exists in the project metadata -> continue; ELSE -> FATAL, show candidates for confirmation`.
3. Confirm the type: `event_property` or `user_property`. This decides `groups[].field.type` in Step 1.
4. `IF there are exactly two valid values -> continue; ELSE -> ERROR, multi-arm or wrong field`.
5. Declare the cohort block and cross-check it: `exposure_event` and the `cohort` block must name the same event.
6. `IF exposure_event == success_event -> ERROR and stop` (exposure equals success, so conversion is undefined).
7. Write the file and run the gate: `IF exit 0 -> proceed to Step 1; ELSE -> fix the fields as instructed and re-run`.

## Error Handling Summary

| Check | Result | Next step |
|-------|--------|-----------|
| Alias normalisation | Exactly one hit | Continue |
| Alias normalisation | Several candidates | Make the user pick; never default to the first |
| Existence | Hit | Continue |
| Existence | Miss | Back to the user (FATAL, stop querying) |
| Value domain | Two groups | Continue |
| Value domain | One or three-plus groups | ERROR, stop |
| Cohort block | Complete and correct caliber | Continue |
| Cohort block | Missing or wrong caliber | ERROR, supply it and re-run |

## Notes

- The gate echoes `lower_is_better_source`. Any value other than `explicit` means the polarity was
  **guessed** and must be confirmed with the user before delivery.
- The order of the values in the group field is **not dependable**. `control_value` /
  `treatment_value` are an explicit declaration, not a row order.
- The `field_mapping.json` produced here is also the optional input that lets Step 1's
  `validate_query_output.py` identify the denominator column.
