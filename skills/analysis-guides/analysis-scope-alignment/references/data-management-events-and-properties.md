# Data Management - Events and Properties

User behavior data can be created as three basic data assets in the system: events, event properties, and user properties, and used in the system's analysis functions.

Event tables and user tables are the lowest-level data available for analysis. Each event can be considered as a fact record template for a certain user behavior or user-related event, with a clear trigger mechanism. When a user actually performs an operation or event, it triggers a report of that event. Event properties are the report items of the event report template, where each property is a characteristic of the event, such as the event's trigger time, trigger person, trigger object, etc., and can also extend to environmental information when the event occurs. Similarly, user properties are report items of the user report template, used to report each user's characteristics, settlements, status, and other information.

During analysis, you can use event properties and user properties for data filtering and grouping, then perform sorting and statistical calculations on the filtered and grouped event and user data.

## 1. Querying Events and Properties

In Data Management, you can query created data assets such as events, event properties, and user properties (some preset events and properties cannot be viewed).

**Event classification is described below:**

| Event Classification | Description |
|---------------------|-------------|
| Preset Events | Events collected by SDK by default, such as App Launch. |
| Custom Events | Events automatically created by the system based on reported data. |
| Virtual Events | Events generated by users through configuring rules in Data Management. |

**Property classification is described below:**

| Property Classification | Description |
|------------------------|-------------|
| Preset Properties | Event properties and user properties collected by SDK by default. |
| Custom Properties | Event properties and user properties automatically created by the system based on reported data. |
| Virtual Properties | Event properties and user properties generated by users through configuring rules in Data Management. |
| Dimension Table Properties | Event properties and user properties automatically generated by users through adding dimension tables for properties in Data Management. |

Click on the event name or property name to view:

- Definition rules for virtual events and virtual properties
- Whether there is an association between events and event properties
- Dimension table structure associated with the property
- Impact scope of the event or property
- Modification and change records of the event or property

The following labels appear after the name on the event/property list page or below the name on the detail page, described as follows:

| Label | Location | Description |
|-------|----------|-------------|
| Hidden | Event/Event Property/User Property | The event or property's display status is hidden. Hidden events or properties cannot be used in analysis. Tags, cohorts, reports, and dashboards that used these events or properties will not be queryable. |
| Disabled | Event | The event is disabled in Data - Instrumentation Management - Report Statistics. After disabling, the event will no longer ingest new data. |
| Timezone | Event Property | The event property is selected as the timezone offset property in Project Management - Project Configuration - Project Timezone. This indicates that the property is the timezone where all events' event time is located, and is also the calculation basis for timezone offset during analysis. |

## 2. Managing Events and Properties

In Data Management, users can:

- Edit the display name and description of events and properties in the system;
- Modify the display or hidden status of events or properties in analysis functions;
- Create virtual events and virtual properties, modify and delete virtual events and virtual properties;
- Add dimension tables for properties to generate dimension table properties, modify and delete property dimension tables to modify and delete dimension table properties;

**Note:** After events and properties are hidden, they cannot be used during analysis. Reports, cohorts, tags, etc. created using these assets cannot be recalculated.
